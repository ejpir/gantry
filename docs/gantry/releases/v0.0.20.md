# Gantry v0.0.20

Gantry v0.0.20 turns the terminal dashboard into a responsive operational
workspace, adds image and registry-credential management to the TUI, removes
unnecessary writable-disk relay overhead, and hardens export, clock, and
cross-process stream handling.

## Highlights

### Operational terminal dashboard

`gantry tui` now opens on an operational overview. Each sandbox card shows its
state and resources alongside recent traffic, transmitted and received bytes,
denied traffic, exposed ports and mounts, and recently denied hosts.

A persistent top navigation bar keeps every production view directly
available:

- Overview
- Sandboxes
- Traffic
- Rules
- Ports
- Packets
- Mounts
- Secrets
- MCP
- Images

The dashboard uses the complete terminal width and reflows for smaller
terminals instead of imposing a fixed maximum width. Cards size themselves to
their rendered content when space is available and shrink or stack when it is
not. Keyboard shortcuts `0` through `9` remain available.

The Sandboxes view now uses a master/detail layout on sufficiently large
terminals. Its detail pane makes the single-VM topology explicit, including the
separate workload and development roots, writable disks, SSH readiness, and
nested Podman profile. Pressing Enter or double-clicking the Workload panel
opens `gantry exec`; double-clicking the creation area opens the New Sandbox
dialog.

New Sandbox remains a global modal opened with `n`. Its settings are grouped
into sections so image, compute, storage, access, Dev Containers, networking,
and isolation options remain understandable without adding another permanent
navigation pane.

Mouse targets are now derived from the same geometry used to render each
component. Padding, borders, clipping, scrolling, responsive reflow, and blank
separator rows therefore cannot move a visible control away from its clickable
region.

### Images and registry credentials in the TUI

The Images view exposes the local OCI cache and the registry credentials used
for pulls. From the dashboard you can:

- inspect image references, digests, architectures, sizes, configuration, and
  whether a saved sandbox uses an image;
- pull an image for a selected Linux architecture;
- remove a selected cached reference or prune every image not referenced by a
  sandbox;
- inspect known registries and the credential source that would be selected;
- store or remove a registry login.

Registry secrets remain write-only in the dashboard. They are not displayed,
returned in snapshots, or placed in command arguments. Gantry prefers a
configured Docker credential helper; when none is available, the dialog warns
that the fallback `~/.gantry/credentials.json` entry is base64-encoded rather
than encrypted.

### Direct workload and IDE writable disks

The workload and curated IDE remain peer OCI environments inside one microVM,
each with an independent writable disk. The supervisor now delegates both disk
descriptors directly to the confined VMM worker instead of relaying block
requests through per-disk IPC brokers.

This keeps independent capacities and the existing disk lifetime locks while
removing avoidable latency from small block I/O.
It does not change `-image` semantics: `gantry exec` still targets the workload,
while SSH and Dev Containers target the IDE environment.

### Security and resilience

- Updates `golang.org/x/crypto/ssh` to v0.55.0, addressing GO-2026-6303.
- Writable-layer exports are bounded by the smaller of the ext4 device size
  and 64 GiB of logical file data. Hard-linked contents count once, stalled
  readers are rejected, and failed exports leave no partial archive.
- runsc hang diagnostics signal only the runtime child supervised by that
  session; Gantry no longer searches guest-global processes and risks
  signalling an unrelated gVisor workload.
- Guest wall-clock synchronization now retries transient virtio-RTC PHC
  timeouts after host suspend or wake instead of stopping until the VM is
  rebooted.
- Split-worker stdio setup performs a short bounded retry before task creation
  when Windows transiently rejects a reconstructed Winsock handle. Retrying at
  that point cannot duplicate guest execution or consume stdin twice.
- Curated IDE image builds use Debian's CDN, retry package downloads, and reuse
  `HTTPS_PROXY` for HTTP mirrors when a separate HTTP proxy is not supplied.
- Reusable Linux field hosts always refresh the guest rootfs, preventing a
  validation run from silently exercising an older vminitd.

## Validation

The release candidate passed the maintained AWS field batteries with staged
host binaries, guest helper, curated IDE image, and patched guest rootfs:

- Linux KVM main battery: **93 passed, 0 failed**
- Linux KVM required/auto confinement: **38 passed, 0 failed**
- Linux KVM SSH, Dev Containers, and large-directory batteries: passed
- Windows WHPX SSH/Dev Containers, isolation, shares, networking,
  secrets/OAuth/MCP, and large-directory batteries: passed

Windows support remains experimental.

## Operational notes

- Existing sandbox configurations require no migration.
- The Overview is the dashboard landing view; New Sandbox remains available
  globally with `n` and from the Sandboxes master pane.
- Image pruning preserves every digest referenced by a saved sandbox.
- Enabling or disabling Dev Containers still requires a sandbox restart because
  the IDE root and writable disk are part of the VM's boot device topology.

See [Images](../images.md), [SSH and Dev Containers](../ssh-access.md),
[Architecture](../architecture.md), and [Security](../security.md) for the
corresponding operational and trust-boundary details.
